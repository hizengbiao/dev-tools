# 正则可视化展示规范化设计

## 目标

统一改进正则表达式四种可视化视图的展示效果：

1. 连续的普通字符合并为一个展示节点。
2. 可显示的字面转义显示转义后的字符，不在节点文字中保留反斜杠。
3. 字符集合拆分为纵向排列的范围或单字符项目。

四种视图包括：

- 匹配路径图
- 正则流程图
- 语法树
- 分段说明

原始正则片段必须继续保留在悬停说明和详细信息中。

## 根因

当前解析器输出的是语法 AST：

- 每个普通字符对应一个 `literal` 节点。
- 转义节点的 `raw` 包含正则源码中的反斜杠。
- 字符集合只保存整体 `raw`，没有展示层的范围项目。

四个视图直接消费语法 AST，因此分别表现为单字符节点、带反斜杠文本和单行字符集合。

这些行为不是匹配解析错误，而是语法结构与展示结构没有分层。

## 方案

新增独立的展示规范化模块 `regex-display-model.js`。模块接收语法 AST，返回 Display AST：

- 保留原始节点类型、位置、量词、分组和说明。
- 增加展示文本、原始片段和字符集合项目。
- 在顺序节点内部合并可安全合并的相邻字面节点。
- 不修改原始 AST。

所有视图统一消费 Display AST，避免在四个渲染器中重复实现规范化规则。

## Display AST 契约

每个展示节点至少包含：

```js
{
    type,
    raw,
    displayText,
    start,
    end,
    description,
    children,
    quantifier,
    characterItems
}
```

其中：

- `raw`：原始正则源码片段，用于悬停说明和错误追踪。
- `displayText`：节点主文字。
- `characterItems`：字符集合拆分结果；非字符集合为 `[]`。
- `children`：已经规范化的子节点。

模块使用 UMD 导出，同时供浏览器和 Node 测试使用：

```js
RegexDisplayModel.createRegexDisplayModel(ast)
```

## 连续字面量合并

### 可合并节点

以下节点可以参加合并：

- 没有量词的普通 `literal`
- 解码后表示单个字面字符、没有量词的 `escape`
- 非 Unicode 模式的字面兼容转义，在能够可靠得到实际字符时

示例：

```text
h t t p              -> http
h t t p \: \/ \/     -> http://
l o c a l h o s t    -> localhost
```

### 合并结果

合并后的节点：

- `type` 为 `literalRun`
- `raw` 为所有源节点原始片段拼接
- `displayText` 为解码后的展示文字拼接
- `start` 为首节点起点
- `end` 为末节点终点
- `sourceNodes` 保留被合并节点的基础信息，便于详细说明

### 不跨越的边界

以下边界禁止合并：

- 量词
- 分组
- 分支
- 锚点和断言
- 字符集合
- 语义转义，如 `\d`、`\s`、`\b`
- 反向引用
- 空节点

合并只发生在同一个 `sequence` 的直接子节点中。

单个普通字符也允许规范化为 `literalRun`，使渲染器只处理一种字面展示类型。

## 转义展示规则

### 字面转义

节点主文字显示解码后的结果：

| 原始片段 | 展示文字 |
|---|---|
| `\.` | `.` |
| `\/` | `/` |
| `\\` | `\` |
| `\:` | `:` |
| `\-` | `-` |
| `\(` | `(` |
| `\)` | `)` |

### 控制字符

不可直接清晰展示的控制字符使用直观中文或转义标识：

| 原始片段 | 展示文字 |
|---|---|
| `\n` | `换行` |
| `\r` | `回车` |
| `\t` | `制表符` |
| `\f` | `换页` |
| `\v` | `垂直制表符` |
| `\0` | `空字符` |

这些控制字符不与相邻普通字符合并。

### 语义转义

继续使用中文语义标签：

- `\d`：数字
- `\D`：非数字
- `\w`：单词字符
- `\W`：非单词字符
- `\s`：空白字符
- `\S`：非空白字符
- `\b`：单词边界
- `\B`：非单词边界

展示文字不包含反斜杠，但 `raw` 保留原始片段。

### Unicode 和十六进制转义

能够可靠解码的字面转义应显示实际字符：

- `\x2e` → `.`
- `\u002e` → `.`
- `\u{1F600}` → `😀`

无效转义不会进入 Display AST，因为解析器会先返回错误。

## 字符集合拆分

字符集合节点增加 `characterItems`。

示例：

```text
[a-zA-Z0-9-]
```

拆分为：

```js
['a-z', 'A-Z', '0-9', '-']
```

### 扫描规则

- 忽略外层 `[`、`]` 和开头的否定符 `^`。
- 未转义的 `x-y` 识别为范围。
- 转义字符作为单个项目，例如 `\-` 显示为 `-`。
- `\d`、`\s` 等语义转义显示中文标签。
- 字符集合中的字面 `]`、`-` 和 `^` 按实际语法位置处理。
- 否定字符集合保存 `negated: true`，说明文字使用“排除以下字符”。

## 四种视图

### 匹配路径图

- `literalRun` 显示为一个节点。
- 字面转义显示解码后文字。
- 字符集合节点内部使用纵向项目列表。
- 节点 `title` 显示完整原始片段和中文说明。

### 正则流程图

- 布局模块改为消费 Display AST。
- `literalRun` 宽度按合并后的 `displayText` 计算。
- 字符集合节点根据项目数量增加高度。
- SVG 使用多个 `<text>` 或 `<tspan>` 纵向绘制字符集合项目。
- 分支、循环和分组框使用自适应后的节点高度重新计算。
- 悬停 `<title>` 保留原始正则片段。

### 语法树

- 顺序节点下显示合并后的 `literalRun`。
- 字面节点显示解码后的文字，旁边保留原始片段；若二者相同，不重复显示。
- 字符集合节点下增加项目列表。
- 原始分组、分支和量词层级保持不变。

### 分段说明

- 每个 `literalRun` 占一行。
- 片段列显示原始片段，含义列显示解码后的展示文字。
- 字符集合项目在单元格中纵向排列。
- 否定集合明确显示“排除以下字符”。

## 安全性

- 所有 `raw`、`displayText` 和 `characterItems` 在写入 HTML 或 SVG 前继续使用 `escapeHtml`。
- Display AST 不包含预拼接 HTML。
- SVG 节点的数据属性和 `<title>` 同样进行转义。

## 验收

自动测试至少覆盖：

- `localhost` 合并为单个 `literalRun`
- `http:\/\/` 展示为 `http://`
- `\.` 展示为 `.`
- `\d` 展示为“数字”且不与字面字符合并
- 带量词节点不参与合并
- 分支和分组边界不跨越合并
- `[a-zA-Z0-9-]` 拆分为四个项目
- 否定集合、转义连字符和语义转义正确拆分
- 四个视图统一消费 Display AST
- 流程图字符集合节点随项目数量增加高度
- 原始片段仍存在于悬停说明中
- `V1.07` 与同日期版本合并

浏览器验收使用用户提供的 URL 正则，确认：

- `http`、`localhost` 等连续字符显示为整体节点
- `\/\/`、`\.` 等显示为 `/`、`.`
- `[a-zA-Z0-9-]` 纵向显示四项
- 四种视图结果一致
- 分支、量词、分组框和路径不重叠
- 控制台无错误
