# 正则流程图视图设计

## 目标

在 `regex-tester.html` 的正则表达式可视化弹窗中新增第四种“正则流程图”视图。该视图参考 Regulex 的图形表达方式，使用连线、分支、回路和嵌套分组框直观展示正则的匹配流程，同时保持现有工具箱的中文文案和视觉风格。

该功能只负责在页面中查看，不提供 SVG 或 PNG 导出。

## 已确认决策

- 新页签名称为“正则流程图”。
- 保留现有“匹配路径图、语法树、分段说明”三个视图。
- 使用现有 `regex-visualizer.js` 生成的 AST 作为唯一数据源。
- 不集成 Regulex 的解析器或渲染源码。
- 采用原生 SVG 绘制节点、连线、分支、回路和分组边框。
- 视觉方向采用 Regulex 布局语义与工具箱统一配色。
- 继续复用现有实时刷新、错误定位和上一次成功结果保留机制。

## 页面交互

在可视化弹窗页签栏中增加“正则流程图”，页签顺序为：

1. 匹配路径图
2. 正则流程图
3. 语法树
4. 分段说明

“匹配路径图”仍是默认页签。用户切换到“正则流程图”时只显示已生成的流程图，不重新解析正则表达式。正则规则或标志变化时，弹窗现有的 250 毫秒防抖刷新会同时更新四种视图。

新页签遵循现有 Tab 无障碍契约：

- 稳定的页签和面板 ID。
- `aria-controls` 与 `aria-labelledby` 双向关联。
- 只允许活动页签进入 Tab 焦点序列。
- 支持左右方向键、Home 和 End 切换。

## 渲染架构

流程图分为布局和 SVG 输出两个阶段。

### 布局阶段

新增独立的流程图布局模块，将 AST 节点转换为带尺寸和坐标的图形节点。每个布局结果包含：

- `width`、`height`
- 主入口和主出口坐标
- 可绘制的节点列表
- 连线路径列表
- 分组边框列表
- 节点原始正则片段和说明

布局函数保持纯函数特性，不直接访问 DOM，方便使用 Node 测试验证坐标和尺寸。

基础节点使用固定最小高度，并根据显示文字计算宽度。布局只使用可预测的字符宽度估算，不依赖浏览器字体测量，避免不同环境产生不稳定坐标。

### SVG 输出阶段

页面将布局数据转换为 SVG：

- SVG 根节点使用布局结果的自然宽高和 `viewBox`。
- 所有正则原始片段、名称和说明均经过 HTML/XML 转义。
- 节点使用 `<g>`、`<rect>`、`<text>`。
- 连线使用 `<path>`，箭头方向通过路径形状表达，不增加复杂 marker 依赖。
- 分组框使用带圆角的虚线 `<rect>`。
- 悬停说明使用 SVG `<title>`。

## 图形语义

### 开始和结束

- 流程图左侧显示绿色开始圆点。
- 右侧显示深灰色结束圆点。
- 两者通过主路径与表达式连接。

### 普通节点

- 普通字面字符使用浅蓝色节点。
- 字符类别和字符集合使用绿色节点。
- 字符集合显示简化内容，如 `3-9`、`a-z`；否定集合在标题或说明中明确“排除”。
- 锚点和边界使用紫色节点，显示“行首、行尾、单词边界”等中文名称。
- 通配符、反向引用和兼容转义使用独立但与工具箱一致的辅助颜色。

所有节点悬停时显示：

- 原始正则片段
- 节点类型
- 直观中文说明

### 顺序

顺序节点从左向右排列，节点之间保留固定水平间距，并使用水平连线连接。

### 分支

`a|b` 等分支使用上下平行路径：

- 入口从主路径分叉。
- 每个分支拥有独立的水平布局。
- 分支宽度按最宽分支对齐。
- 出口重新汇入主路径。
- 分支之间保留足够垂直间距，避免连线或节点重叠。

### 量词

- `?` 和 `{0,1}` 使用上方绕过路径表达“可以跳过”。
- `*` 和 `{0,n}` 同时显示绕过路径与下方回环路径。
- `+` 和 `{1,n}` 显示下方回环路径。
- `{n}`、`{n,}`、`{n,m}` 在节点下方显示中文次数说明。
- 懒惰量词在次数说明后增加“优先少匹配”。
- 回环使用红色路径，与主流程的蓝灰色路径区分。

首期只表达匹配结构和次数范围，不模拟正则引擎的完整回溯优先级。

### 分组与断言

- 捕获分组使用蓝灰色虚线边框，标题为“捕获分组 1”或命名分组名称。
- 非捕获分组标题为“非捕获分组”。
- 前瞻、后瞻等断言使用不同的紫色虚线边框，并显示中文断言名称。
- 分组框根据内部流程布局扩展尺寸。
- 嵌套分组使用嵌套边框，保持每层标题可见。

## 复杂表达式与滚动

流程图保持自然宽高，不压缩节点。视图面板继续使用弹窗内部横向和纵向滚动。

布局增加保护：

- 最大可绘制节点数量沿用解析器的节点保护。
- 限制生成 SVG 的最大宽高。
- 坐标或尺寸异常时显示“流程图过于复杂，请简化正则表达式”，不影响另外三个视图。
- 空表达式显示开始和结束圆点以及一条直接连接线。

## 样式

采用已确认的工具箱统一风格：

- 主连线：蓝灰色
- 开始圆点：绿色
- 结束圆点：深灰色
- 字面节点：浅蓝色
- 字符类别：浅绿色
- 锚点与边界：紫色
- 重复回路：红色
- 分组框：蓝灰色或紫色虚线
- 背景：白色或当前弹窗背景

不照搬 Regulex 的灰色背景、英文节点或高饱和经典配色。

## 文件边界

- 新建 `regex-flow-layout.js`
  - 提供 UMD 导出。
  - 负责 AST 到流程图布局数据的转换。
  - 不访问 DOM。
- 新建 `tests/regex-flow-layout.test.cjs`
  - 测试顺序、分支、量词、分组、嵌套和复杂度保护。
- 修改 `regex-tester.html`
  - 增加第四个页签和面板。
  - 将布局数据渲染为 SVG。
  - 增加流程图样式并接入统一刷新。
- 修改 `tests/regex-tester.test.cjs`
  - 验证页面接线、页签无障碍、SVG 安全输出和版本信息。

将布局算法拆出单独文件，是为了避免继续扩大 `regex-tester.html` 中的内联脚本，并允许对坐标和路径进行真实行为测试。

## 测试与验收

自动测试至少覆盖：

- 页面存在“正则流程图”页签和对应面板。
- 四个页签的 ARIA 关联、焦点状态和键盘切换正确。
- 顺序表达式生成从左到右的节点和连线。
- 分支生成平行路径并在出口汇合。
- `?`、`*`、`+` 和范围量词生成正确的绕过或回环路径。
- 捕获组、非捕获组、断言和嵌套分组生成正确的边框层级。
- 空表达式生成开始到结束的直接路径。
- 用户正则片段经过 SVG/XML 转义。
- 布局复杂度和尺寸保护返回可展示错误。
- 实时刷新和上一次成功结果机制包含新视图。
- 版本更新为 `V1.06`，同日期说明正确合并。

浏览器验收至少覆盖：

- 默认手机号正则的流程图与参考图语义一致。
- `^(a|b)*?$` 能看到分支、跳过路径、循环和懒惰说明。
- URL 等复杂正则的分组框、分支和滚动区域不重叠或裁切。
- 切换四种视图不重新解析且无控制台错误。
- 修改规则后流程图自动更新。
- 无效规则时流程图保留上一次成功结果。
- 390px 和桌面宽屏下弹窗、页签和 SVG 滚动正常。
