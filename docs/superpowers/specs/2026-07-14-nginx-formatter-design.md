# Nginx 配置格式化工具设计

## 目标

在现有纯前端开发者工具箱中新增 Nginx 配置格式化工具。工具参照 `json-parser.html` 的交互风格，支持格式化和结构级语法检查，并在格式化过程中保留原配置中的注释。

## 范围

### 包含

- 格式化常见 Nginx 配置及配置片段。
- 保留独立注释和指令后的行尾注释。
- 检查花括号、分号、单双引号、注释和指令基本结构。
- 报告错误所在的行、列、错误类型及简短说明。
- 提供示例、复制和清空操作。
- 将工具注册到首页、顶部导航、项目文档及浏览器冒烟测试清单。

### 不包含

- 不校验具体指令名称、参数数量或指令所在上下文。
- 不绑定特定 Nginx 版本或第三方模块指令表。
- 不自动修复存在结构错误的配置。
- 不执行 `nginx -t`，也不访问本地或远程 Nginx 环境。
- 不提供配置压缩、树形编辑或语义重排。

## 方案选择

采用轻量词法解析器，逐字符识别普通文本、空白、单双引号字符串、`#` 行注释、分号和花括号。该方案比正则替换更能正确处理引号中的 `#`、`;` 和花括号，同时比完整 Nginx 语法树更轻量，适合当前结构级检查需求。

## 页面与交互

新增 `nginx-formatter.html`，保持现有工具的原生 HTML、CSS、JavaScript 实现方式，并沿用 `json-parser.html` 的页面观感和主操作区布局。

页面包含：

- 原始配置输入视图，带行号。
- 格式化结果视图，带行号并设为只读。
- “格式化”“复制结果”“清空”“加载示例”按钮。
- 状态区，显示格式化成功摘要或语法问题。
- 结构摘要，显示指令数、配置块数、注释数和最大嵌套深度。

默认使用四个空格缩进。点击格式化后，输入为空时显示提示；输入合法时切换到结果视图；输入有结构错误时保留输入内容、显示全部可定位问题，并清空旧结果，避免把旧内容误认为当前结果。

## 解析与格式化

新增 `nginx-formatter.js`，以 UMD 风格同时支持浏览器调用和 Node 测试。它提供以下独立能力：

- 分词：扫描配置并生成带起止位置的标记。
- 分析：统计指令、块、注释和嵌套深度，同时收集结构问题。
- 格式化：在校验通过后按照标记序列生成规范化文本。

格式化规则：

- `{` 位于所属块声明之后，块内容增加一级缩进。
- `}` 单独成行，并减少一级缩进。
- 普通指令以 `;` 结束并单独成行。
- 指令内部多余空白归一为单个空格，但不修改引号中的内容。
- 独立注释保持为独立行，保留在其相邻指令或块之间。
- 行尾注释保留在对应指令或块声明之后，并用单个空格隔开。
- 注释文本本身不改写。
- 输出统一使用 `\n` 换行，并去除行尾空格和多余的首尾空行。

## 结构检查

检查器报告以下问题：

- 多余或缺失的 `{`、`}`。
- 未闭合的单引号或双引号。
- 文件结尾仍未以 `;` 或块结束符完成的指令。
- `{` 前缺少块声明。
- `;` 前缺少指令内容。

`#` 注释持续到当前行末，无需闭合。检查器允许任意指令名称和参数内容；引号内的花括号、分号和 `#` 均作为普通字符处理。每个问题包含零基位置和面向页面显示的一基行列信息。

## 文件与集成

- `nginx-formatter.html`：页面布局和交互。
- `nginx-formatter.js`：解析、格式化和检查逻辑。
- `tests/nginx-formatter.test.cjs`：核心逻辑测试。
- `nav.js`、`index.html`：新增工具入口。
- `browser-smoke-manifest.js`：新增页面冒烟测试项目。
- `tests/tool-registry.test.cjs`：验证注册完整性。
- `README.md`、`DEVELOPMENT.md`：补充工具说明。

## 测试策略

核心测试覆盖：

- `http`、`server`、`location` 等多层嵌套块的缩进。
- 多条指令位于同一行时的拆分。
- 独立注释、行尾注释及块边界附近注释的位置保留。
- 引号内包含 `#`、`;`、`{`、`}` 及转义引号。
- 空输入、仅注释输入和不带外层块的配置片段。
- 多余或缺失花括号、缺失分号和未闭合引号的行列定位。
- 统计信息的正确性。

集成验证运行新增核心测试、工具注册测试和浏览器冒烟测试，最后运行项目完整测试集，确认未影响现有工具。

## 成功标准

- 合法配置格式化后结构清晰，连续格式化两次的结果相同。
- 注释内容及相对归属不会因格式化丢失。
- 结构错误能够定位到具体行列，且不会产生格式化结果。
- 页面可直接通过静态文件和 GitHub Pages 使用，无构建步骤和外部依赖。
- 首页、导航、文档和测试清单均能发现新工具。
