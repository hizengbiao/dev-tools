# 正则表达式可视化功能设计

## 目标

在现有 `regex-tester.html` 中增加正则表达式可视化功能，帮助用户理解正则的匹配顺序、语法层级和各片段含义。功能必须保持当前工具的单页、无构建依赖和统一视觉风格，不影响已有的匹配、替换、高亮及结果输出能力。

## 已确认范围

- 支持浏览器 JavaScript 正则表达式语法。
- 兼容工具当前支持的 `(?i)` 前缀，并将其转换为忽略大小写标志后再解析。
- 不扩展为 Java、PCRE 等多语言正则解析器。
- 提供匹配路径图、语法树、分段说明三种视图，用户可在弹窗内自行切换。
- 使用大尺寸弹窗承载可视化内容。
- 弹窗打开期间，正则表达式或正则标志变化时自动刷新。
- 无效或不支持的语法需要显示错误位置和原因，同时保留上一次成功生成的可视化结果。

## 页面交互

在“匹配规则”输入区域增加“正则可视化”按钮。点击按钮后：

1. 打开大尺寸可视化弹窗。
2. 立即解析当前匹配规则和正则标志。
3. 默认展示“匹配路径图”。
4. 用户可切换到“语法树”或“分段说明”，切换时复用已有解析结果。
5. 弹窗打开期间，匹配规则或标志发生变化时，经过约 250 毫秒防抖后自动重新解析并刷新当前视图。
6. 关闭弹窗后停止可视化刷新，原测试页面的输入和结果状态保持不变。

弹窗提供关闭按钮和标题“正则表达式可视化”。内容区域允许横向滚动，保证复杂表达式不会被压缩到难以阅读。

## 解析架构

实现一个不依赖第三方库的轻量解析器，分为三个职责明确的阶段：

### 1. 标准化

- 复用现有正则规则预处理逻辑。
- 识别表达式开头的 `(?i)`，移除该前缀并合并到标志集合。
- 保留每个字符在原始输入中的位置映射，用于错误定位和片段展示。

### 2. 解析

词法扫描和递归下降解析生成统一抽象语法树。首期节点类型包括：

- 表达式与顺序序列
- 分支 `|`
- 字面字符
- 转义字符及常见字符类别，如 `\d`、`\w`、`\s`
- 字符类及否定字符类，如 `[a-z]`、`[^0-9]`
- 捕获分组、非捕获分组和命名捕获分组
- 开始与结束锚点
- 单字符通配符
- 量词 `*`、`+`、`?`、`{n}`、`{n,}`、`{n,m}` 及懒惰量词
- 正向或反向断言等 JavaScript 支持的分组结构
- 反向引用

每个节点包含类型、原始片段、起止位置、子节点、量词信息和可读说明。捕获分组保存分组编号或名称。

解析失败时返回结构化错误：

- 错误消息
- 原始表达式中的字符位置
- 出错片段

### 3. 渲染

三个渲染器只消费统一语法树，不自行重新解析表达式。这样可保证三种视图对同一语法结构的解释一致。

## 三种视图

### 匹配路径图

- 从左向右展示匹配顺序。
- 顺序节点使用连线连接。
- 分支使用上下分叉路径表达。
- 分组显示边框、分组编号或名称。
- 量词显示重复范围和贪婪或懒惰状态。
- 锚点、字符类、通配符等采用容易区分的节点样式。
- 节点悬停时显示原始片段、节点类型和直观说明。
- 画布支持横向滚动；首期不增加拖拽、缩放或导出图片功能。

路径图优先采用 HTML 与 CSS 布局，必要连接线使用局部 SVG。SVG 只承担连线，不承载主要文字内容，以便保持可访问性和响应式布局。

### 语法树

- 以可展开的层级结构展示父子节点。
- 每一项显示节点类型、原始片段和简短含义。
- 分组显示编号或名称。
- 分支、量词和断言明确显示其子结构。
- 默认展开全部节点；复杂表达式允许逐级折叠。

### 分段说明

使用表格展示：

- 原始片段
- 类型
- 直观含义
- 匹配次数或约束
- 所属分组

表格按表达式的阅读顺序排列。容器节点可展示为分组行，其子片段继续按层级缩进。

## 状态与错误处理

可视化模块维护：

- 当前解析结果
- 上一次成功解析结果
- 当前选中的视图
- 当前错误
- 弹窗是否打开

解析成功时替换当前和上一次成功结果，并清除错误。解析失败时：

- 在弹窗顶部显示错误原因和字符位置。
- 在表达式片段中突出出错字符附近的内容。
- 三种视图继续显示上一次成功结果，并标注“以下为上一次成功解析结果”。
- 如果从未成功解析，则只显示错误和空状态。

解析和渲染必须设置复杂度保护，限制最大输入长度、节点数量和递归深度。超过限制时给出明确提示，避免复杂或恶意表达式导致页面卡顿。

## 样式与响应式

- 沿用现有颜色、按钮、边框、圆角、弹窗和版本说明风格。
- 弹窗在桌面端占据大部分视口，但保留外边距和关闭入口。
- 小屏设备上弹窗接近全屏，页签可横向滚动。
- 路径图保持其自然宽度，通过内部滚动查看，不强行压缩节点。
- 不引入新的图标库或外部资源。

## 测试与验收

自动测试至少覆盖：

- 页面存在“正则可视化”入口、弹窗和三个视图页签。
- 默认手机号正则可生成稳定的语法树。
- 顺序、分支、嵌套分组、字符类、量词、锚点和转义能够正确解析。
- `(?i)` 能与现有规则保持一致。
- 无效正则返回准确错误位置。
- 解析失败后保留上一次成功结果。
- 输入变化使用防抖刷新，弹窗关闭时不刷新。
- 复杂度限制能够阻止过长、过深或节点过多的表达式。
- 版本号和版本说明已更新。

浏览器验收包括：

- 三种视图可正常切换。
- 修改规则或标志后弹窗内容自动更新。
- 错误提示不会覆盖或清除上一次成功结果。
- 路径图在桌面和窄屏下均可滚动查看。
- 现有测试匹配、执行替换、复制、行号和版本说明功能无回归。
