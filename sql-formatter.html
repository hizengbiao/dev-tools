SQL 书写顺序与逻辑执行顺序

输入 SQL 后打开手册，将高亮这条 SQL 实际使用的环节。
“真正执行”指逻辑处理顺序：数据库优化器可能重排 JOIN、下推过滤条件或合并子查询。要确认某次查询的物理执行计划，请使用 EXPLAIN / EXPLAIN ANALYZE。

① SQL 书写顺序

从上到下阅读 SQL 时，各子句通常按这个语法顺序出现。

  1. 1WITH / CTE先声明公共表表达式
  2. 2SELECT写出最终需要返回的列或表达式
  3. 3DISTINCT紧跟 SELECT，声明结果去重
  4. 4FROM指定主数据源
  5. 5JOIN追加要关联的数据源
  6. 6ON书写表之间的关联条件
  7. 7WHERE过滤原始行
  8. 8GROUP BY指定分组字段
  9. 9HAVING过滤分组后的结果
  10. 10UNION组合多个查询的结果集
  11. 11ORDER BY指定最终结果排序
  12. 12LIMIT / OFFSET限制或跳过最终返回行

② 逻辑执行顺序

可理解为每个阶段接收上一步结果并继续处理的顺序。

  1. 1WITH / CTE建立可供主查询引用的命名查询
  2. 2FROM读取查询的基础数据源
  3. 3JOIN引入另一数据源并准备组合行
  4. 4ON保留满足关联条件的组合
  5. 5WHERE在分组前剔除不符合条件的行
  6. 6GROUP BY将剩余行按键归入各个分组
  7. 7HAVING依据聚合结果筛选分组
  8. 8SELECT计算并投影最终输出列
  9. 9DISTINCT删除重复的输出行
  10. 10UNION合并分支结果；UNION 会额外去重
  11. 11ORDER BY对完整输出结果排序
  12. 12LIMIT / OFFSET最后截取需要返回的结果窗口

关键字速查与常见误区

阶段这一阶段做什么实用提醒
FROM / JOIN / ON建立初始行集并完成表关联。外连接中，把条件放在 ON 还是 WHERE 可能改变结果；优化器也可能调整物理 JOIN 顺序。
WHERE聚合前按行过滤，减少后续要处理的数据。因为 SELECT 尚未逻辑执行，通常不能在 WHERE 中引用 SELECT 别名。
GROUP BY / HAVING先分组和计算聚合，再由 HAVING 过滤分组。能在 WHERE 提前过滤的条件不要全部放入 HAVING；部分数据库允许 HAVING 使用 SELECT 别名，但可移植性不同。
SELECT / DISTINCT生成输出列，再按需对整行结果去重。此时产生的列别名可供后面的 ORDER BY 使用。
UNION纵向合并各查询分支，UNION ALL 保留重复行。最终 ORDER BY / LIMIT 通常写在整个组合查询末尾。
ORDER BY / LIMIT先排序，再截取最终结果窗口。没有稳定 ORDER BY 时，LIMIT 返回的具体行并无可靠顺序保证。
